# Phase 8: Global Observability & Notifications Hub

## Goal
Provide a comprehensive, cross-workflow observability interface for organization owners and editors, allowing them to monitor executions and view system alerts globally, without requiring them to drill down into individual workflow pages.

## Features Implemented
- **Global Execution Runs (`/runs`)**: A dedicated page displaying a unified timeline of all `workflow_runs` across all workflows within the active organization. Users can view status, duration, start/completion times, and navigate directly to the specific workflow.
- **Notifications Hub (`/notifications`)**: A dedicated page for viewing all alerts generated by the `notify` workflow step across the organization. Provides message context and links to the source workflow.
- **Dashboard Enhancements (`/dashboard`)**: Added aggregate metrics showing the total number of workflow executions and total failed executions. Replaced the generic "Recent Workflows" list with "Recent Executions" and "Recent Notifications" widgets for immediate operational visibility.
- **Navigation Integration**: Updated the application sidebar to include direct links to "Global Runs" and "Notifications".

## Security & Architectural Alignment
- **Tenant Isolation**: All new GraphQL queries are strictly filtered using `where: {org_id: {_eq: $orgId}}` (or nested equivalent). Tenant isolation continues to rely safely on Hasura's Phase 2 metadata rules enforcing `X-Hasura-User-Id` mapping via `org_members`.
- **Zero Schema Migrations**: Phase 8 was implemented purely through frontend components and GraphQL queries utilizing the existing `workflow_runs`, `notifications`, and `workflows` tables. No database migrations were required, respecting the strict freeze on the Phase 2 schema.
- **Read-Only Visibility**: The new dashboards are strictly observational and rely on standard `select` permissions already granted in Phase 2.

## Testing & Validation
- **Structural Tests (`test-phase8.mjs`)**: Verified the existence of UI components, navigation links, and the presence of strict `org_id` scoping inside the GraphQL queries.
- **Authenticated Live Tests**: Marked as `BLOCKED (AUTH VERIFICATION)` due to the absence of verifiable Nhost testing identities in the local development environment.
- **Quality Gates**: `npm run lint` and `npm run build` pass with zero errors.

## Known Limitations
- The dashboard aggregate queries (e.g. `workflow_runs_aggregate`) are fetched in real-time. For extremely high-volume organizations (e.g., millions of runs), these queries may become slow without proper indexing. However, given the architectural constraints against schema/infrastructure changes, no new indices were added. The performance is deemed acceptable for the current scale.
